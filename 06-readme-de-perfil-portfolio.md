# README de perfil — seu portfólio no GitHub

Além do repositório de prática `minha-primeira-aula`, você pode criar um **README de perfil**: ele aparece na página principal do seu GitHub, como um cartão de visitas e mini portfólio.

## Exemplo do professor

Veja o perfil do professor como referência:

**https://github.com/eduardo97mendes**

Lá você encontra:
- Apresentação pessoal e profissional
- Tecnologias organizadas por área
- Projetos em destaque
- Informações que contam sua história além do código

Seu perfil não precisa ser igual — use como inspiração e adapte ao seu momento.

---

## Como funciona o README de perfil

O GitHub mostra um README especial na sua página quando você:

1. Cria um repositório **público**
2. Com o **mesmo nome do seu usuário** do GitHub

| Seu usuário | Nome do repositório |
|-------------|---------------------|
| `maria-silva` | `maria-silva` |
| `joao-dev` | `joao-dev` |

Dentro desse repositório, o arquivo `README.md` vira a "capa" do seu perfil.

### Passo a passo

1. Descubra seu usuário (canto superior direito do GitHub → clique na sua foto)
2. Vá em **+** → **New repository**
3. **Repository name:** digite **exatamente** seu nome de usuário
4. Marque **Public**
5. Marque **Add a README file**
6. Clique em **Create repository**
7. Edite o `README.md` e faça commit

Pronto — abra `https://github.com/SEU-USUARIO` e veja o resultado.

## Como montar um README de portfólio

Pense no README como uma **vitrine**. Quem visitar seu GitHub deve entender em poucos segundos:

- Quem você é
- O que você sabe fazer
- O que está aprendendo
- O que você já construiu (ou pretende construir)

### Estrutura recomendada

Use esta ordem — do mais importante para o complementar:

```
1. Título + frase de apresentação
2. Sobre mim (quem sou, o que faço, onde estudo/trabalho)
3. Tecnologias (já sei / aprendendo / quero aprender)
4. Projetos em destaque
5. Contato e links
```

---

## Seção de tecnologias — organize em 3 níveis

Não invente habilidades. Seja honesto — recrutadores e professores valorizam clareza.

### Já sei / Domino

Ferramentas e linguagens que você **já usou em projeto, aula ou prática** e se sente confortável para explicar.

Exemplos: HTML, CSS, Git, Canva, Word, Excel, Python básico.

### Estou aprendendo

O que você está estudando **agora**, em curso, escola ou por conta própria.

Exemplos: JavaScript, React, PHP, GitHub, Figma, impressão 3D.

### Quero aprender

Tecnologias e áreas que você **planeja** estudar nos próximos meses.

Exemplos: Node.js, banco de dados, inteligência artificial, desenvolvimento mobile.

### Dica de organização

Separe por área quando fizer sentido:

- **Desenvolvimento Web** — HTML, CSS, JavaScript...
- **Ferramentas** — VS Code, Git, GitHub, Figma...
- **Outras áreas** — design, 3D, games, automação...

No perfil do professor, as tecnologias aparecem com **badges** (aquelas etiquetas coloridas). Isso é opcional — comece com listas simples em Markdown.

## Modelo básico para copiar

Substitua tudo entre colchetes pelo seu conteúdo:

```markdown
# Olá, eu sou [SEU NOME]! 👋

[Uma frase sobre você — ex: "Estudante de programação apaixonado por criar sites."]

---

## 🚀 Sobre mim

- 🎓 [Onde estuda ou o que cursa]
- 💻 [O que está fazendo agora — curso, projeto, estágio]
- 🎯 [Seu objetivo principal — ex: virar desenvolvedor web]
- 💬 Pode me perguntar sobre [assuntos que você domina]

---

## 🛠️ Tecnologias

### ✅ Já sei
- [Tecnologia 1]
- [Tecnologia 2]
- [Tecnologia 3]

### 📚 Estou aprendendo
- [Tecnologia 1]
- [Tecnologia 2]

### 🎯 Quero aprender
- [Tecnologia 1]
- [Tecnologia 2]

---

## 📂 Projetos em destaque

| Projeto | Descrição | Link |
|---------|-----------|------|
| [Nome] | [O que o projeto faz] | [link do repositório] |
| [Nome] | [O que o projeto faz] | [link do repositório] |

> Se ainda não tem projetos, escreva: *"Projetos em construção — atualizando sempre!"*

---

## 📫 Contato

- GitHub: [@SEU-USUARIO](https://github.com/SEU-USUARIO)
- LinkedIn: [seu perfil ou "em breve"]
- E-mail: [seu e-mail ou "disponível mediante solicitação"]
```

## Boas práticas de portfólio no GitHub

### Faça

- Escreva de forma clara e objetiva
- Atualize quando aprender algo novo
- Linke repositórios reais nos projetos em destaque
- Use português correto (ou inglês, se preferir — seja consistente)
- Mostre evolução: "estou aprendendo" hoje pode virar "já sei" amanhã

### Evite

- Listar 20 tecnologias que nunca usou
- Deixar o README vazio ou com texto genérico copiado
- Prometer projetos que não existem (melhor dizer "em construção")
- Expor dados pessoais sensíveis (endereço, telefone, documentos)

## Evolução do seu perfil

Seu README pode crescer com você:

| Momento | O que colocar |
|---------|----------------|
| **Primeira aula** | Nome, sobre mim, 3 tecnologias, objetivos |
| **Após 1 mês** | Projetos da aula, lista de estudos atualizada |
| **Após 3 meses** | Tabela de projetos, badges (opcional), estatísticas |
| **Portfólio maduro** | Cases reais, links para deploy, contribuições open source |

## Badges e estatísticas (nível avançado — opcional)

Quando estiver confortável com Markdown, você pode adicionar etiquetas visuais:

```markdown
![HTML](https://img.shields.io/badge/HTML5-E34F26?style=flat&logo=html5&logoColor=white)
![CSS](https://img.shields.io/badge/CSS3-1572B6?style=flat&logo=css3&logoColor=white)
![JavaScript](https://img.shields.io/badge/JavaScript-F7DF1E?style=flat&logo=javascript&logoColor=black)
```

Estatísticas do GitHub (opcional):

```markdown
![Estatísticas](https://github-readme-stats.vercel.app/api?username=SEU-USUARIO&show_icons=true&locale=pt-br)
```

Troque `SEU-USUARIO` pelo seu nome de usuário. Isso não é obrigatório na primeira aula.
